## Claims to keep out of the README without fresh evidence

1. **ComfyUI as the active image-generation backend or Machine B as a LAN worker.** The stack survey recommends ComfyUI at [`20260609-image-gen-stack.md:305`](/Users/alcatraz627/Code/local-models/docs/research/20260609-image-gen-stack.md:305), while [`docs/TODO.md:9`](/Users/alcatraz627/Code/local-models/docs/TODO.md:9) says the image-generation slice became `imagine` on mflux and the ComfyUI path was dropped. That same TODO says the LAN offload and Qwen3-VL plans were not pursued (`:10`).
2. **`OLLAMA_USE_MLX=1` as a setup requirement, or a blanket Ollama MLX speedup.** The runtime survey recommends it at [`20260609-runtime-orchestration.md:343`](/Users/alcatraz627/Code/local-models/docs/research/20260609-runtime-orchestration.md:343) and `:356`. [`bin/lm-serve:21`](/Users/alcatraz627/Code/local-models/bin/lm-serve:21) records that this variable never existed and that Ollama chooses the runner from model format; [`docs/STATE.md:41`](/Users/alcatraz627/Code/local-models/docs/STATE.md:41) states the current architecture.
3. **June model inventory and proposed vision picks as installed/current.** The vision survey says Gemma4 26b/31b were present and then calls `gemma4:27b` “already present” at [`20260609-vision-models.md:216`](/Users/alcatraz627/Code/local-models/docs/research/20260609-vision-models.md:216); it recommends pulling Qwen3-VL at `:225`. [`docs/STATE.md:52`](/Users/alcatraz627/Code/local-models/docs/STATE.md:52) lists current tiers, including `minicpm-v` for vision. Its star ratings, memory sizes, load times, and “best open-weight” verdict are survey estimates, not project measurements.
4. **Suggested image models as working `imagine` options.** The consolidated guide lists Ideogram, Z-Image, and Kontext, marking some as absent from its registry at [`20260610-imagegen-techniques.md:20`](/Users/alcatraz627/Code/local-models/docs/research/20260610-imagegen-techniques.md:20). Current [`bin/imagine:29`](/Users/alcatraz627/Code/local-models/bin/imagine:29) has explicit cases for schnell, dev, qwen, and Flux.2; its fallback passes other names to `mflux-generate` and does not establish that those models are usable. Do not copy “best model,” OCR score, speed, licensing, or support claims from the June tables as current facts.
5. **`imagine critique` as future work.** The consolidated guide calls it “next” at [`20260610-imagegen-techniques.md:91`](/Users/alcatraz627/Code/local-models/docs/research/20260610-imagegen-techniques.md:91) and proposes adding it at `:104`. [`bin/imagine:283`](/Users/alcatraz627/Code/local-models/bin/imagine:283) contains the subcommand now. This is source evidence of implementation, not a runtime result.
6. **Exact seed continuity when switching models.** The pipeline note claims a seed chosen with schnell should reproduce the composition in dev at [`20260610-imagegen-pipeline.md:303`](/Users/alcatraz627/Code/local-models/docs/research/20260610-imagegen-pipeline.md:303)-`:317`. Treat that as an untested recipe: a numeric seed is reproducible only under a sufficiently fixed model and generation configuration; the README should not promise cross-model composition preservation.
7. **Research recipes as verified output quality or current CLI flags.** The local-workflows and pipeline notes contain measured-sounding speed, memory, OCR, and quality claims and commands for several separate runners. The README should use the repo's present command help and observed results for operational examples, then link these notes as dated research.
