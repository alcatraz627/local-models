## Attacks that held

- Full-table arithmetic: `/Users/alcatraz627/Code/local-models/probe/fixtures/table-contract.py:19` exercises 3,000 rows and confirms the final row drives the maximum. The parser runs before the generic context cap at `/Users/alcatraz627/Code/local-models/bin/q:368`, so this path does not silently profile a prefix.
- Malformed row width: the same contract rejects a short CSV row with structured `ctx_unsupported`, and `/Users/alcatraz627/Code/local-models/lib/data-profile.py:115` checks every row.
- Fleet pass semantics: `/Users/alcatraz627/Code/local-models/lib/fleet:176` separates a nonempty envelope gate from an optional content judge. The new docs explicitly say an envelope pass is not correctness proof. `/Users/alcatraz627/Code/local-models/lib/fleet-review.py:71` binds human verdicts to source, result, and index hashes.
- RAG reindex safety: `/Users/alcatraz627/Code/local-models/lib/rag.py:97` embeds and validates vector count and dimension before building a staged SQLite DB, then replaces the destination at line 131. This protects the existing index from ordinary embedding and insertion failures. The search path checks embedder identity and query dimensions at lines 140-146.

## Verification boundary

I read the changed functions, their direct CLI callers, the table contract, the benchmark fixture, the RAG wrapper, and fleet review consumers. I ran isolated parser and chunker probes, plus a `/private/tmp` workbook preflight probe. I did not call Claude models, run a new Ollama model request, re-run the parent’s 41-check suite, or run live retrieval quality trials. The converter failure observed in this sandbox is an environment limitation; finding 2 rests on the CLI ordering and the preflight result, not a claim that production XLSX conversion is broken.
